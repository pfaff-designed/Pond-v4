1bring in a file

Dropping running-log.html in the composer attaches it above the line. Pond offers what it can do with it. The page underneath is unchanged.

wheredrop in the composer, attach with ＋ in the composer or the zen pill, or ⌘K › import a page, which opens the file chooser. All four land here.
on a pagedropped on a page, an html file becomes an attachment card like any other file. Only the composer turns it into a page.
capturean html file is a capture like any upload. Pond proposes its home, and asks when unsure.
chipsmake this a page, or file it as it is. Typing anything else works too.
one eachone proposal per file. Several files make several proposals.

2reading

Pond reads the file in the composer. The answer says what it has found so far, and the read row names the file and its size. The page doesn’t move.

foundcounts as it goes: headings, text, tables, charts, images.
stopesc stops. Nothing has been made, so there is nothing to undo.
unsureif a table could be a database or a short list of facts, Pond asks one question with chips before it proposes, as in 7k.
reachreading looks only at the file and the images it links to.

3the proposal

The answer is a make this a page card: name, place and kind filled in, then the blocks it will build, in page order.

cardthe same card as any answer that becomes a page. make page accepts, change place moves it before it’s made, cancel rejects, and typing below requests changes.
blocksonly Pond’s own: text, headings, lists, checklists, tables, databases, charts, quotes, images, files. No html is pasted.
tablesa table with dates, or rows you’ll add to, becomes a database with a table view. A short table of facts stays a table block.
chartsa chart must read a table, so Pond rebuilds it on the table it was drawn from. If the file has only the picture, Pond makes the table from its values, or lists the chart as not carried over.
imagesimages in the file or linked from it become image blocks. Images drawn by a script can’t be read and are listed.

4what isn’t carried over

Under the blocks, a second card names every part with no matching block, and why. Those parts stay in the file, which is kept on the page.

namedeach part by what it is: the map, the site’s links, styling, a form.
keptthe file is the page’s last block, so nothing is lost.
beforelisted before you accept. Nothing disappears silently.
